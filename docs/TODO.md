- 원래 계획한 5-3(혼입 가능성 따로 표시)이 꼭 필요하다는 것을 확인했다. 5-3에 이 경우를 테스트 사례로 추가한다.

## 4단계: 사진에서 글자 읽기 (완료)

목표: 사진을 올리면 원재료명 글자가 입력칸에 채워진다.

- [x] 4-1. 사진 찍기/고르기 버튼, 끌어다 놓기, 붙여넣기 만들기 (PRD #4-2)
- [x] 4-2. Tesseract.js로 한국어 글자 인식하는 `js/ocr.js` 만들기 (PRD #4-2, #7)
- [x] 4-3. 인식 전 사진 전처리 (확대, 조명 얼룩 펴기, 대비 높이기) (PRD #4-2, 0단계 결과)
- [x] 4-4. 인식 진행률 표시와, 실패했을 때 직접 입력하라는 안내 (PRD #4-2, #3)
- [x] 4-5. 앱 안에서 카메라 켜고 촬영하기: 후면 카메라, 가이드 틀, 틀 영역만 잘라 인식 (PRD #4-6) *(10/29 추가)*
- [x] 4-6. 카메라를 쓸 수 없을 때(권한 거부, https 아님) 사진 고르기로 안내 (PRD #4-6, #7) *(10/29 추가)*

확인 방법: 예시 라벨 사진을 올리거나 앱 안 카메라로 찍으면 글자가 채워지고 판정이 바뀐다.

알게 된 것:
- 가짜 카메라 영상(라벨 이미지)으로 앱 안 카메라 → 촬영 → 글자 인식 → 판정까지 한 번에 이어지는 것을 확인했다.
- 글자가 없는 잡음 사진을 넣었더니 숫자와 한글이 뒤섞인 엉터리 글자가 나왔고, 한글이 8자를 넘어서 "읽기 성공"으로 처리됐다. 엉터리 글자 속 단어가 성분으로 잡히면 잘못된 판정이 나올 수 있어서, 한글 비율(35% 이상)과 인식 확신도(40 이상)를 함께 보도록 바꿨다.
- 바꾼 뒤 잡음 사진은 확신도 14로 걸러졌고, 라벨 사진 4장은 확신도 82~92로 모두 통과했다.

## 5단계: 결과 다듬기 (완료)

목표: 매장에서 한눈에 판단할 수 있게 결과를 정리한다.

- [x] 5-1. 이유 목록: 어떤 성분이 어떤 조건에 걸리는지 한국어 원문과 함께 표시 (PRD #4-4)
- [x] 5-2. 인식한 성분의 한국어·영어 표 만들기 (PRD #4-3)
- [x] 5-3. "같은 제조시설" 문구의 성분을 혼입 가능성으로 따로 표시 (PRD #4-5)
- [x] 5-4. 원문에 걸린 성분 강조 표시 (PRD #4-4)
- [x] 5-5. 아는 성분을 하나도 못 찾았을 때 "문제 없음" 대신 "판단할 수 없음" 표시 (PRD #3, #10, 0단계 결과)
- [x] 5-6. 한국어/영어 화면 전환: 브라우저 언어로 시작, 선택 기억, 성분은 한국어 원문 함께 표시 (PRD #4-7) *(10/29 추가, 제안-1에서 이동)*

확인 방법: 예시 3종과 흐린 사진에서 판정, 이유, 표, 강조가 모두 맞게 나온다.

알게 된 것:
- 3단계에서 발견한 "같은 제조시설" 오판정을 고쳤다. 초코 과자 + 땅콩 알레르기는 "먹을 수 없음"에서 "땅콩 혼입 가능성(확인 필요)"으로, 라면 + 돼지고기 X는 "먹을 수 없음"에서 "문제 없음"으로 바뀌었다. 테스트 사례 5개를 추가해 30개 모두 통과.
- 한국어 화면을 만들다 보니 할랄 이유에 "쇠고기 포함"만 나오고 "도축 방식 모름"이 빠지는 문제가 보였다. 식단 이유에서는 알레르기 이름 대신 식단 설명을 쓰도록 고쳤다.
- 판정 카드에 다른 언어 한 줄을 같이 보여 주기로 했다. 외국인이 점원에게 화면을 보여 줄 때나, 한국인 친구가 설명해 줄 때 바로 통하게 하려고.

## 6단계: 실제 포장 사진 대응 *(10/29 테스트 후 추가)*

목표: 실제 포장 사진에서 원재료명만 골라 제대로 읽는다.

배경: 실제 캔 음료 사진(파란 바탕 흰 글자)을 넣었더니 아무것도 읽지 못했다. 색 반전, 원재료 줄만 자르기, 3배 확대까지 해 봐도 "정세수 설탕 기다과당 구여사"처럼 절반 넘게 틀렸다(확신도 45~55). 또 사진 한 장에 주소, 소비기한, 보관 방법이 함께 찍혀 원재료가 아닌 글이 섞였다.

- [ ] 6-1. 흔한 원재료(감미료, 기름, 전분, 산미료, 무기질, 비타민, 향료, 색소, 증점제, 채소·곡물·과일 등) 300개 이상을 사전에 추가 (PRD #4-3)
- [ ] 6-2. 결과에 "원재료 N개 중 M개 인식" 표시 (PRD #4-3, #10)
- [ ] 6-3. 찍거나 고른 사진 위에 네모 칸을 띄우고, 사용자가 원재료명 영역을 지정 (PRD #4-8)
- [ ] 6-4. 흰 글자 라벨(어두운 바탕) 자동 감지해 색 반전 (PRD #4-2)
- [ ] 6-5. 글자 인식 중계 서버(Cloudflare Workers) 코드 작성. API 키는 서버에만 저장 (PRD #7)
- [ ] 6-6. Gemini API로 지정 영역의 원재료명·알레르기 표시·같은 제조시설 문구만 옮겨 적기 (PRD #4-2, #7)
- [ ] 6-7. AI 인식이 실패하면 브라우저 안 인식기로 대신하고, 어느 방식으로 읽었는지 화면에 표시 (PRD #7)

확인 방법: 실제 캔 음료 사진에서 영역을 지정하면 원재료가 대부분 맞게 읽히고, 성분표에 영어 이름과 인식 개수가 나온다.
